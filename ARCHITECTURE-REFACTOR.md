# Fastly LMS: Architecture v3 (Express API + Next.js web + Capacitor mobile)

Status: proposed · Replaces the single Next.js app (server actions + Drizzle/Postgres inside Next).
Source of truth for product rules stays `docs/objective.md`. This file only covers **how the code is split**.

---

## 1. Why change

| Today | Problem |
|---|---|
| Backend lives inside Next.js (server actions, Drizzle/Postgres access, Clerk server helpers, webhook route) | Cannot be reused by a mobile app. Web and data logic are welded together. |
| Pages are server components that read the DB directly | A Capacitor app cannot run a Next server, so these pages cannot ship in a native shell. |
| `cacheComponents`, `proxy.ts`, `x-pathname` header | Next-server features that do not exist in a static/mobile build. |

Goal: one **API** that owns all data and rules, and one **web UI** (Next.js) that is a pure client of that API and can also be wrapped by **Capacitor** for Android/iOS.

## 2. Decisions

| # | Topic | Decision |
|---|---|---|
| D1 | Backend | Express 5 + TypeScript in `apps/api`. Drizzle ORM + PostgreSQL, zod, Clerk backend, svix move here. |
| D2 | Frontend | Next.js 16 (App Router) in `apps/web`. **No database access, no server actions, no Drizzle/Postgres code.** |
| D3 | Rendering | Web is **client-rendered and statically exported** (`output: "export"`). Data comes from the API with a fetch client. One build serves browser and Capacitor. |
| D4 | Auth | Clerk stays. Web signs users in with Clerk's React SDK and sends `Authorization: Bearer <session token>`. API verifies the token. Role and status still come from Clerk `publicMetadata` (`role`, `status`, `onboarded`), mirrored in Postgres by webhook. |
| D5 | Authorization | Enforced **only on the API**. The web UI hides things for UX, but never decides access. |
| D6 | Shared code | `packages/shared` holds zod validators, role/status constants, and API response types. Both apps import it. No duplicated schemas. |
| D7 | Mobile | Capacitor wraps the static web build (`apps/web/out`). Capacitor config and native projects live inside `apps/web`. |
| D8 | Pattern | Plain MVC on the API: `routes -> controllers -> db (Drizzle schema + queries)`. No services layer, no repositories. |
| D9 | Tooling | bun workspaces. One lockfile (`bun.lock`). Delete `package-lock.json`. |
| D10 | Everything else | Product rules (roles, statuses, enrollment flow, invoices, audit log) do not change. |

## 4. API (apps/api)

### 4.1 Request flow
`route -> middleware (auth, role, validate) -> controller -> Drizzle query -> audit (if needed) -> JSON`

### 4.2 Conventions
- Base path `/api/v1`. Areas: `/me`, `/admin/*`, `/teacher/*`, `/student/*`, `/parent/*`, `/catalog/*`. Webhooks at `/webhooks/clerk` (outside `/api/v1`).
- Response envelope (matches today's `ActionState`):
  `{ ok: true, data }` or `{ ok: false, error: "message" }`. Validation errors return 400, unauthenticated 401, forbidden 403, missing 404, conflict 409.
- Every controller input is validated with a zod schema from `packages/shared`.
- Role gate in the route (`requireRole("admin","super_admin")`), **record-level ownership check in the controller** (a parent only their children, a teacher only their students, a student only themselves). Keep the existing rules from `lib/auth/*` and `actions/*` exactly.
- Multi-record writes (role change + audit, reassignment) use `db.transaction(async (tx) => ...)` and pass `tx` to every query inside it. Postgres supports this on any plan, no special setup.
- Every admin action that changes a role, status, teacher or board writes an audit log entry, as now.
- Time stored in UTC, shown in Asia/Karachi (UI concern). Money is whole PKR integers.
- Security middleware: `helmet`, `cors` (allowlist below), `express-rate-limit` on auth-adjacent and write routes, JSON body limit, one central error handler that never leaks stack traces.

### 4.3 Auth
- Use Clerk's Express SDK (`@clerk/express`) or `@clerk/backend` token verification. **Check Clerk's current docs for the exact API before coding; do not guess.**
- `auth` middleware verifies the bearer token and loads a `GateUser` (role, status, onboarded) using the same logic as `checkAccess` in `lib/auth/roles.ts`.
- Missing metadata is treated as `pending`. `suspended` gets 403 on everything. A student who is `active` but not `onboarded` can only call onboarding endpoints.
- Webhook (`/webhooks/clerk`): needs the **raw body** for svix signature verification, so mount it before `express.json()`. Behavior identical to today's route (creates the user as `pending`, links accepted parent invites).
- Parent invite stays on Clerk's backend invitation API, called from the API.

### 4.4 CORS allowlist
`WEB_ORIGIN` (production site), `http://localhost:3000` (dev), and Capacitor's origins: `capacitor://localhost` (iOS) and `https://localhost` / `http://localhost` (Android, depending on `androidScheme`). Allow the `Authorization` header. No wildcard.

### 4.5 Environment (apps/api/.env.example)
```
PORT=4000
DATABASE_URL=
CLERK_SECRET_KEY=
CLERK_PUBLISHABLE_KEY=
CLERK_WEBHOOK_SIGNING_SECRET=
WEB_ORIGIN=
EMAIL_*=              (whatever lib/email.ts uses today)
```

### 4.6 Database (PostgreSQL + Drizzle)
- The schema is **moved as it is**. Do not rename tables or columns and do not change types in this refactor, so existing data and migrations keep working.
- `apps/api/drizzle.config.ts` points at `src/db/schema` and `src/db/migrations`. Scripts: `db:generate`, `db:migrate`, `db:studio`.
- Use Drizzle's query builder/relations in controllers. Keep queries parameterized (never string-built SQL).
- Reads that went to the client select only the columns the response needs.
- Whatever id type the schema uses today (uuid, serial) stays; the shared types use the same type.

## 5. Web (apps/web)

### 5.1 What gets removed
`drizzle-orm`, `drizzle-kit`, the Postgres driver, `@clerk/nextjs` server helpers, `proxy.ts`, `actions/`, `lib/queries`, `db/` (schema, migrations), `app/api/*`, `cacheComponents`, `export const instant`, `x-pathname`.

### 5.2 What it becomes
- `next.config.ts`: `output: "export"`, `images: { unoptimized: true }`, `trailingSlash: true`.
- Auth: `@clerk/clerk-react` (`ClerkProvider`, `useAuth`, `SignIn`, `SignUp`, `UserButton`) in a client layout. If `@clerk/nextjs` still works in export mode for the pieces needed, it may stay; verify against Clerk docs. Do not rely on Clerk middleware.
- `lib/api-client.ts`: a small typed fetch wrapper that attaches the Clerk token, parses the envelope, and throws on `ok: false`. Base URL from `NEXT_PUBLIC_API_URL`.
- Data fetching: TanStack Query (or SWR) in client components. Lists use URL search params for search/filter/page.
- Mutations call the API, then invalidate the relevant queries and show the error or success message.
- **Route guards are UX only**: a client layout per panel calls `GET /me`, redirects by role/status (`ROLE_HOME`, `/pending`, `/rejected`, `/onboarding/parent`, `/?error=account_suspended`), and shows a skeleton while loading. The API remains the real gate.
- **Dynamic routes**: static export cannot render unknown ids. Replace `[id]` segments with a query param, e.g. `/admin/courses/detail?id=...`, read with `useSearchParams` inside a Suspense boundary. Affected: admin users/courses/books, teacher classes/students, parent children, and any other `[id]` route.
- Keep the active-nav highlight with `usePathname`.

### 5.3 Env (apps/web/.env.example)
```
NEXT_PUBLIC_API_URL=
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=
```

## 6. Mobile (Capacitor, added last)

- `capacitor.config.ts`: `appId` (reverse-DNS, e.g. `pk.fastly.lms`), `appName`, `webDir: "out"`, `server.androidScheme: "https"`.
- Scripts in `apps/web`: `build` (next build, produces `out/`), `cap:sync` (`cap sync`), `cap:android`, `cap:ios` (open native IDE).
- Plugins to start with: `@capacitor/app` (back button, deep links), `@capacitor/status-bar`, `@capacitor/splash-screen`, `@capacitor/keyboard`.
- UI for native: safe-area insets (`env(safe-area-inset-*)`), `viewport-fit=cover`, 44px touch targets, no hover-only controls, sidebar becomes the existing Sheet drawer.
- Android hardware back button handled via `@capacitor/app`.
- Deep link for parent invites (`/invite`) configured in the native projects.
- **Clerk in a native webview is the main risk.** Clerk has no dedicated Capacitor SDK. Email/password and email-code sign-in should work inside the webview. Social OAuth redirects may not. Do a small spike early (see phase 6) and record the result here.
  - Fallback if the spike fails: Capacitor `server.url` pointing at the hosted web app, accepting that the app then needs a network connection.
- App Store note: a thin wrapper around a website can be rejected by Apple. Keep native features (status bar, back button, deep links, offline shell) so it behaves like an app.

## 8. Phases

Each phase ends with passing checks and a commit. Work on branch `refactor/api-split`.

- [ ] **0. Baseline.** Run build, lint, lint:colors. Record results. Confirm `qa/` PNGs exist.
- [ ] **1. Monorepo scaffold.** bun workspaces, `apps/api`, `apps/web`, `packages/shared`. Move the current Next app into `apps/web` unchanged and confirm it still runs.
- [ ] **2. Shared package.** Move validators, role/status enums, `ActionState`/envelope types. Update imports.
- [ ] **3. API foundation.** Express app, env, Drizzle client, error handler, auth + require-role middleware, `/health`, `/me`, Clerk webhook. Test auth with a real token.
- [ ] **4. Port domains to the API,** one domain at a time (onboarding/requests, admin users, catalog, enrollment, teacher, student, parent, assessment, support, invoices, audit log). For each: routes, controllers, same guards and audit entries, plus a test for ownership rules.
- [ ] **5. Web cut-over.** Add api-client, Clerk React auth, client guards. Convert pages domain by domain to API calls. Replace `[id]` routes. Delete server actions, queries, models, proxy, webhooks from web. Turn on `output: "export"`.
- [ ] **6. Capacitor spike.** Add Capacitor, build, run on an Android emulator. Test Clerk sign-in (email code and OAuth). Record the outcome in section 6.
- [ ] **7. Capacitor finish.** Plugins, safe areas, back button, deep links, splash/icon, `cap:android` and `cap:ios` scripts.
- [ ] **8. Cleanup.** Remove unused files and dependencies, delete `package-lock.json`, rewrite README (run instructions for api, web, mobile), update `docs/objective.md` stack and structure sections.

## 9. Risks and open questions

| Risk | Mitigation |
|---|---|
| Clerk OAuth inside a native webview | Phase 6 spike; fallback to email-code sign-in or `server.url` |
| Static export removes server rendering (SEO, first paint) | Acceptable: app is behind login. Public pages (landing, sign-in) are static and fine. |
| Database connections: pooling and migrations | One shared pool in the API only. Run `drizzle-kit migrate` as a deploy step, never from the web app. If the host is serverless Postgres (Neon, Supabase pooler), use its pooled connection string. |
| Cookie vs bearer auth confusion | Bearer token only; no cookies between web and API |
| Two deploys instead of one | API on Render/Railway/Fly, web on Vercel or any static host, mobile via store builds |
| File uploads (`fileUrl` provider still open in objective.md) | Out of scope here; keep storing a URL only |

Open questions for the owner: API hosting provider, file storage provider, bundle id / app name, whether iOS is needed now or Android only.

## 10. Definition of done

- API runs alone (`bun run dev` in `apps/api`) and every previous server action exists as an endpoint with the same guards, audit entries and validation.
- Web has no Drizzle/Postgres code, no server actions, no DB access, and builds with `output: "export"`.
- Role and status gating behaves exactly as before; parent/teacher/student isolation is enforced and tested on the API.
- App runs on an Android emulator (and iOS if in scope) with sign-in and at least one full flow working.
- `bun run build`, `bun run lint`, `bun run lint:colors` pass in every package.
- No unused files, exports or dependencies. `qa/` PNGs untouched. README and `docs/objective.md` match this file.
